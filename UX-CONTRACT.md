## Appearance

Dark is the default on every public and staff screen, including projector, sign-in and forced password reset. ThemeScript resolves a valid localStorage siklab-theme value (dark/light) before body paint; absent, invalid or inaccessible storage uses dark regardless of OS appearance. ThemeProvider owns live state without reloading or remounting workspaces. A shared, labeled 44px-minimum ThemeToggle changes the document appearance immediately and remembers the preference when storage is available. Blocked storage preserves switching within the current document. Storage changes synchronize open tabs; clearing or invalidating the stored preference returns other tabs to dark. Theme selection is browser-local, never an account field, URL filter or API payload.

Both palettes and all semantic foreground/background pairs are owned by theme.css. Logos remain unmodified on light identity plates; status meaning never depends only on color. Native controls follow color-scheme, print uses the light palette, and forced-colors/reduced-motion behavior remains operable. Theme changes preserve filters, route/history, open dialogs, entered values and drafts. Root markup defaults to dark without JavaScript, and applying a saved light preference must not flash dark content or emit hydration warnings.

## Navigation/state

URL owns college, category, date, venue, status, page, mode, bracket and round. Changing filters resets page. Event changes reset bracket/round/mode. A selected event defaults to competition cards. Only explicit mode=bracket opens a complete published bracket; Schedule cards remain available. Category selection resets mode. Date and status shortcuts write the same URL filters as the labeled native controls. Without a bracket, retain the date-grouped agenda. Filters highlight bracket fixtures, never remove connections. Phone round selection and match links update the URL. Back/forward restores state.

The leaders strip appears on every public route and stays pinned during document scrolling. It derives campus-wide official points from approved championship awards and authorized tally corrections using overall(), independent of filters. Exactly three teams are shown when official totals exist, with actual shared ranks and an additional-tied-teams link when the cutoff is tied. No awards or nonzero corrections shows an awaiting-standings state. The full seven-team tally precedes the timeline on phones and stays sticky beside it on desktop. Gold/Silver/Bronze counts combine championship podium placings and authorized corrections; the breakdown identifies aggregate official adjustments without private actors or reasons.

Overview chooses today or the next scheduled day before applying its timeline-only college filter. All statuses remain visible, succession follows predecessors, and the official tally remains campus-wide. Results opens seven banners in catalog order, three latest published outcomes or completed field events per college, identified by schedule ID; each college link opens 20-per-page history. Secondary tournament/sub-point data is complete and independent of pagination.

## Save and publication

BracketEditor uses StaffApp.run for busy, idempotency, success and errors. Save draft leaves public content intact. Publish validates the full graph and updates its publication atomically. Version conflicts preserve entered values; reload is explicit. Preview uses the same public bracket component. In-editor cancel is an explicit discard confirmation; browser unload warns for unsaved changes. Bracket editor is isolated from other event navigation while dirty.

## Role and publication workflow

Game staff (`officer`) only create/update assigned schedules and statuses, including Completed. Administrator and superadministrator controls own results, entries, brackets, optional championship awards and exact college totals. The primary administrator tally control is Manage official tally. Accounts, full system audit and recovery remain superadministrator-only.

ResultEditor selects an explicit winner/draw with an optional paired score; absent scores never imply a draw. Completed placing/field events derive public history from the schedule without fake revisions. Head-to-head completion alone awaits an administrator result. New results/awards have Save draft and Publish actions; existing pending submissions retain publish/reject review. Certified standings bypass schedule-result prerequisites while preserving confirmed rules and candidate/college policy. Calculated standings retain detailed-result prerequisites.

PublishConfirmation and TallyImpactPreview own publication confirmation when an award changes, comparing all seven colleges before/after with server-checked expected totals and rule versions. Award replacement removes the old contribution. Certified awards do not change on result corrections; calculated impacts publish atomically. Draft inputs preserve candidate rows even when best-entry aggregation collapses the displayed award. Safe schedule metadata editing retains scoringVersion; edits affecting scoring remain locked by saved results/calculated awards.

## Data ownership

Fixtures own actual participants, logistics and statuses; approved result revisions own explicit decisions and optional scores. Slots describe advancement only. Published byes advance known entrants; unresolved results, ties and double forfeits do not. Corrections never modify fixtures. Inconsistent paths and their descendants display reconfirmation warnings and stop advancement until administrators repair the connections or assigned staff update fixture logistics as permitted.

## Async states

usePublicData polls every five minutes with jitter while visible, refreshes on visibility and reconnection, and aborts old requests. Public requests omit staff cookies. Manual refresh remains available, and freshness labels describe when a response was checked; a 15-second approved-data cache does not imply five-minute automatic polling is live. Initial failure has no cached-data claim. Refresh failure keeps matching-query data with a stale notice; previous-filter data is never shown as current. Empty and no-match states offer recovery links. No optimistic publication.

## Shared identity and score presentation

Stored BUHI remains canonical in database records and URLs; all visible college-code labels display BC. Branding metadata owns department names, mascot names and local logo paths. Crests are decorative when adjacent text already names the team. Custom participant labels remain intact. Every numeric score, time, medal count and rank uses tabular numerals.

Match cards show only approved results. Ongoing is a schedule status, not a running score. Placing competitions show entrants or approved placings without forcing them into head-to-head layouts. Shared scheduleTimeLabel distinguishes fixed times, After [competition], and Time TBA. Schedule pages use compact cards with 20-item pagination and preserved URL filters. Two-college diagonal clash gradients use canonical tokens; fields with more than two distinct colleges use all seven college colors. Only an approved unambiguous winner receives a winner tint; ties/shared winners/double forfeits retain competing colors. Rainbow accents remain low-opacity behind readable card surfaces. Secondary result details expand without obscuring outcome, participants, score or date.

## Staff workflows

Staff and auth roots share the broadcast visual theme. Desktop sidebar and contained phone tabs preserve officer/admin/superadmin visibility. Officers manage assigned schedules/statuses only; administrators manage event operations, review, rules and tally corrections; only superadministrators receive accounts, assignments and full audit history. Scoped revisionActors supply display names for event history without account records. No leaders strip is added to staff forms. StaffForm preserves HTML required/email/min/max constraints with checkValidity and inline validation, focus and field descriptions; it does not use browser validation popups. StaffApp.run and client.api retain canonical mutation/retry/session behavior. Button-triggered StaffDialog editors close only on success; validation/conflicts preserve inputs. Dirty dismissal asks for confirmation, busy requests prevent dismissal, and closing restores trigger focus. Toasts appear bottom-right on desktop/bottom-center on phones above dialogs; actionable errors remain inside the dialog. Sign-in and mandatory reset remain dedicated screens. Review queue shows ten compact rows per page with detailed review in a dialog. Private drafts and direct publication are separate actions; the review queue is retained for legacy pending submissions. Official match and championship rules are owned by docs/OFFICIAL_RULES.md and the verified server command schemas.

Schedule date is required, but both times may be empty. Clearing start also clears end; end is unavailable without start. Succession clears both times and requires a predecessor. TBA never implies midnight or a fictional reserved interval. Status uses mutually exclusive radio choices. Ordered college controls replace free-text tie lists, and each official podium rank has a labeled numeric points input.

Tally corrections accept desired nonnegative integer Points/Gold/Silver/Bronze totals and a reason of at least ten characters. A second step names the college, before/after totals, differences and immediate publication. tally.correct compares expectedTotals within the serialized transaction, rejects stale/no-op corrections and appends signed offsets separately from awards. Subsequent awards continue adding normally; award publication that would make final totals negative is rejected for reconciliation. Corrections use the existing idempotency and public invalidation pipeline; only aggregate offsets are public.

Backup download remains private and uses a short-lived signed attachment link. The file picker accepts one non-empty JSON backup up to 25 MB; upload progress, cancellation and retry preserve the selected file. Restore/reset use modal preview and confirmation editors owned by BackupPanel, StaffDialog and StaffForm. The server binds each preview to the owner, checksum, database revision and a 15-minute expiry. Restore requires the current password and explicit replacement consent. Competition reset requires the current password and the exact phrase RESET EVENT DATA; it retains staff, assignments, college entries, configured rules and administrative history while clearing manual tally corrections. Backups export version 5 with explicit outcomes, award provenance, draft inputs, scoring versions and the correction ledger; versions 2–4 remain supported, with absent legacy tables normalized. Both actions require a successfully persisted private safety backup and sign everyone out on success. Ten safety copies are retained; temporary import/export objects expire after 24 hours. Passwords are masked with a labeled reveal button, remain only in the form, and are never placed in URLs or persistent storage. Cancellation clears confirmation inputs and restores trigger focus. Expired previews disable execution and direct a fresh preview. A timed-out destructive operation is treated as uncertain completion and requires signing in to inspect saved state before another attempt; it is never retried automatically. Forced password reset remains an explicit sign-in transition.
